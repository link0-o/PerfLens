### 2026-10-05 JDK 副本数据文件权限修正

用户随后提供的 Python 3.12/3.13 CI 日志均在 pytest 前停止，报错为
`Staged JDK preflight failed: ... JDK runtime payload identity is unsafe`。日志显示源
`go`、`java` 可执行文件为 `0777`，但未记录源 payload 的权限。此前准备脚本把任何带执行位
的文件复制成 `0755`，遗漏了 JDK 数据文件 `release` 和 `lib/modules`；生产门禁对这两者
只接受 `0444` 或 `0644`，拒绝是正确的。分别给任一 payload 加执行位，以及整树 `0777`
fixture，都复现了完全相同的错误；修复前三个复现用例均失败。

准备脚本现在仅将这两个独立副本规范化为 `0644`，并在预检前输出有界身份元数据；其他
可执行文件（含 `lib/jspawnhelper`）保留 `0755`。24 项准备回归通过，覆盖源身份不变、
离线构建匹配 pprof，以及生产校验仍拒绝可执行 payload。本次修复没有修改生产权限规则、
源工具链、覆盖率门槛、commit 或 Tag。真实 Go 1.24.4、Temurin JDK 17.0.20.1 的整树
`0777` 副本也通过修正后的准备流程与两个 Adapter 预检。这是本地复现，不据此断言日志
未记录的远端 payload 权限，也不能替代修复源码上的远端 CI 重跑。
使用上述准备后的运行时、固定 `0022` umask，本地全量测试通过：Python 3.13.5 为
**2,390 项、覆盖率 85.29%**（265.73 秒）；Python 3.12.13 为 **2,390 项、覆盖率 85.30%**
（292.73 秒），两者均无失败、错误或跳过，均执行了真实 Java 子进程/JFR 转换及 Go
Launcher 路径。Ruff、Pyright（含准备脚本）、wheel/sdist 构建与隔离安装冒烟也通过。

## 候选范围

pthread、Java JFR、CPython threading 与 Go pprof Adapter。Docker optimization Preview
也可以显式把 Runtime Lock 权限纳入同一次用户确认。它不增加 JVM/native/Python live
注入、不向任意已有容器注入、不扩大特权 Helper capability，也不自动 commit、push、Tag
或发布。
