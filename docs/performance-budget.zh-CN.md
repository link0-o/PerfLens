# PerfLens 性能预算

简体中文 | [English](performance-budget.md)

里程碑 1 的目标是建立经过测量的基线，而不是承诺未经测量的绝对吞吐量。可复现测试器
会在临时文件中生成 folded 记录，通过公开 Application Service 完成分析，并记录墙钟
时间、每秒记录数、每秒输入字节数和峰值 RSS。

语料规模：

- 小型：1,000 条记录；
- 中型：100,000 条记录；
- 大型：1,000,000 条记录。

运行：

```bash
python tests/performance/benchmark_folded.py \
  --records 1000 100000 1000000 \
  --repetitions 3
```

CI 使用小型语料作为冒烟基线。正式发布前的专用运行会把准确的操作系统、架构、Python
版本、输入大小、耗时、吞吐量和峰值 RSS 记录到本文档。

## 已记录基线

测量日期为 2026-07-30，环境如下：

- Linux 6.12.74、Debian 13、x86_64；
- Python 3.13.5、GCC 14.2.0；
- 单进程、冷启动生成输入、精确聚合；
- 100 个唯一叶子符号和 3 个共享父符号。

下表给出三次重复运行的耗时和吞吐量中位数，以及观测到的最大进程 RSS。原始数据记录
在 `docs/performance-baseline.json`。

| 语料 | 输入 | 耗时中位数 | 每秒记录数中位数 | 输入 MiB/s 中位数 | 最大 RSS |
|---|---:|---:|---:|---:|---:|
| 小型（1,000） | 27,900 字节 | 0.0094 秒 | 106,814 | 2.84 | 30.8 MiB |
| 中型（100,000） | 2,790,000 字节 | 0.7316 秒 | 136,682 | 3.64 | 32.7 MiB |
| 大型（1,000,000） | 27,900,000 字节 | 7.6194 秒 | 131,245 | 3.49 | 32.7 MiB |

峰值 RSS 是 `getrusage` 报告的整个进程内存高水位，不是隔离的内存分配测量。中型到
大型语料的 RSS 基本不变，是因为本语料使用流式样本且基数受限；唯一 Frame 和调用路径
状态仍会随基数增长，直到触发明确的硬上限。

CI 故意对 1,000 条记录使用较宽的冒烟阈值：10 秒和 1 GiB。它用于发现数量级回退，
不会把共享 Runner 的噪声当成性能失败。在设置更严格预算之前，发布基线必须保留原始
重复测量值。

## 最终发布验证

里程碑 9 完成后，于 2026-07-30 再次运行了同一测试器。1,000、100,000 和 1,000,000
条记录的吞吐量中位数分别是 92,852、104,038 和 102,429 条/秒；最大 RSS 为
33.8 MiB。当时主机还在下载依赖并执行隔离环境检查，因此这些值作为“发布负载下的
观测”保留，不替换上面的安静环境参考基线。它们仍远低于已发布的 CI 冒烟护栏，并且
保持了中型到大型语料 RSS 基本平坦的预期形态。
