# PerfLens v0.3.2 Docker Optimization Regression Playbook

[简体中文](v0.3.2-regression-playbook.zh-CN.md) | English

This is the post-v0.3.2 maintainer contract for failures that were fixed during release hardening.
It is not a list of active defects. See [Known issues](known-issues.md) for versioned symptoms and
[Troubleshooting](troubleshooting.md) for operator recovery. Do not move the published `v0.3.2`
tag to include this document.

## Required managed-collection sequence

The `stat` and `record` path must retain this order:

```text
Preview and one explicit authorization
  → build and verify a session-owned Build
  → issue one workload lease
  → create the container with package Gate blocking PID 1
  → optional PMU availability probe (never reports ready)
  → start the selected formal profile with events disabled
  → perf acknowledges the disable barrier
  → revalidate PID/UID/start time/namespace/cgroup
  → perf acknowledges enable
  → emit exactly one Broker-ready frame; Gate execves the workload
  → finish collection, publish Artifacts, verify and clean the container
```

An availability probe, test double, fallback branch, or error path must never release the Gate.
Ready means that the selected formal profile is bound to the same revalidated target; it does not
mean merely that Docker is reachable, `perf_event_open` succeeded, or authorization exists.

## Fixed failures and permanent invariants

### 1. Unsupported perf `ping` control command

- Historical symptom: the disabled-event binding handshake failed before Gate release; test
  doubles passed while real Linux perf failed.
- Cause: public `perf stat/record --control` supports `enable` and `disable` but does not promise
  `ping`.
- Invariant: start with `-D -1`, use idempotent `disable → ACK` as the binding barrier, revalidate
  the target, then send a distinct `enable → ACK`. Test doubles must not accept commands that the
  production perf protocol does not support.

### 2. PMU probe released a fast workload

- Historical symptom: a slower baseline collected successfully while an optimized candidate
  exited before the formal profile bound; changing to `software_only` appeared to help
  intermittently.
- Cause: the availability probe and formal profile shared the Gate-ready callback.
- Invariant: the probe has no ready callback and only the selected formal profile may release the
  Gate once. Zero cycles/instructions on a blocked Gate do not prove that a PMU will count the real
  workload, even if scheduling fields are present. `auto` may fall back conservatively;
  hardware evidence requires explicit `hardware_required`.

### 3. Control deadline, pipe backpressure and false fallback

- Historical symptom: slightly slow startup or verbose perf diagnostics caused intermittent
  handshake failure, and `auto` could incorrectly attempt software collection.
- Invariant: `disable → identity revalidation → enable` shares one bounded, child-liveness-aware
  startup deadline. The Python Collector drains bounded diagnostic pipes while waiting. Timeout,
  early exit, channel closure and invalid ACK are `perf_control` infrastructure failures, not PMU
  unavailability; they never trigger fallback or release Gate. Do not mask the race with an
  unbounded wait or a larger global pytest timeout.

### 4. Accounting after workload-lease failure

- Historical risk: when no Collection was produced, an Agent could treat the attempt as unused,
  switch `stat`/`record`, or continue building in the same Session.
- Invariant: failure after lease issuance is charged exactly once, releases unused time/evidence
  reservations, and permanently blocks further build/collection in that Session. It cannot be
  retried unchanged, switched to another evidence mode, or charged to the recoverable build/test
  retry budget. A pre-lease rejection is not charged but still requires a real correction. After
  infrastructure repair, obtain a new Preview and authorization.

### 5. Candidate exists without an A/B Iteration

- Historical risk: collection or correctness stopped before comparison, while the former
  finalizer required an Iteration and encouraged treating a Build ID as an Iteration ID or
  inventing `not_comparable`.
- Invariant: create a `not_evaluated` Disposition bound to the latest `candidate_build_id` and a
  typed `evaluation_reason`. Restoring baseline needs no acceptance token; retaining an unevaluated
  candidate requires fresh explicit consent. Human choice records workspace state and never
  creates or upgrades a performance conclusion.

### 6. Benchmark magnitude never overrides evidence quality

- `Verified Improvement` requires matching `actual_event_source`, fixed environment, correctness,
  Benchmark, verified Profile evidence, acceptable resource transfer and deterministic replay.
- A `partial` Profile, restricted kernel `[unknown]` weight, or lower-bound cgroup delta is not
  erased by a large wall-time improvement. When user-space symbols are complete but kernel frames
  are restricted, report the two separately and never attribute kernel unknown weight to a user
  function.
- With no Iteration, use `not_evaluated`. Use `not_comparable` only when an Iteration exists but its
  evidence cannot support comparison.

### 7. Container identity, cgroup, Artifact, and symbol boundaries

- `Docker target pid namespace identity is unavailable` does not mean that an Agent confirmation
  popup was skipped. Docker results and `/proc/<host-pid>` PID namespace, start time, UID, and
  cgroup identity must jointly prove the target; any missing binding rejects before collection.
- When a short-lived container removes its cgroup, use only the pre-pinned `O_PATH` anchor and the
  last identity-verified snapshot, and mark resource deltas as `partial` lower bounds. Never widen
  an allowed root, follow a replaced pathname, or report the lower bound as exact.
- A semantic workload fingerprint may remain stable across sessions, but every timestamped
  WorkloadSpec/Collection Artifact needs a unique content-bound ID. Same-ID/different-content is a
  collision or tampering signal and is never repaired by deleting old evidence.
- Verified container-module/user-source identity and restricted kernel symbolization are separate
  quality dimensions. Kernel `[unknown]` must neither downgrade a verified user module nor be
  attributed to it.

## Forbidden shortcut fixes

- Report ready during PMU probing, capability inspection, or immediately after container creation.
- Treat zero hardware counts as usable or relabel `perf_control` failure as software fallback.
- Retry a failed collection or change mode inside the same optimization Session.
- Weaken PID, namespace, cgroup, path, or Artifact identity checks to keep the workflow moving.
- Delete colliding Artifacts, globally prune Docker objects, or bypass the Broker with direct
  Docker/perf commands.
- Skip Profile, resource, or correctness gates because a Benchmark improvement is large.
- Present a human-retained candidate as `Verified Improvement`.

## Regression-test map

Changes to Collector, Helper, Gate, PMU fallback, optimization state or the MCP finalizer must run
at least:

```bash
.venv/bin/pytest -q \
  tests/unit/test_collector_broker_security.py \
  tests/integration/test_collector_broker.py \
  tests/unit/test_docker_optimization_runtime.py \
  tests/mcp/test_server.py

cargo test --locked --package perflens-privileged-helper
```

The key contracts include:

- `test_cap_perfmon_auto_probe_keeps_managed_gate_blocked_until_formal_profile`;
- `test_cap_perfmon_does_not_misclassify_control_failure_as_pmu_fallback`;
- `test_cap_perfmon_does_not_retry_formal_control_failure_as_software`;
- `test_failed_workload_is_charged_and_blocks_unchanged_session_retries`;
- `test_runtime_finalizes_unevaluated_candidate_after_collection_failure`;
- Rust `perf_binding_allows_a_slow_live_startup_within_the_bounded_window`,
  `auto_collection_does_not_hide_control_failure_with_software_fallback`,
  `formal_hardware_stat_requires_a_usable_requested_counter`, and
  `auto_collection_falls_back_to_fixed_software_events_within_the_duration`.

These focused tests do not replace the Python 3.12/3.13, coverage, Ruff, Pyright, Schema, Rust
fmt/clippy/test/audit/deny, reproducible-package and DEB-smoke gates in the
[release process](releasing.md).

## Real-host acceptance assertions

After installing matching main and Collector packages, restarting all three services, and
reloading the Agent/MCP connection, use a newly authorized short session. Never reuse the failed
Session. Confirm at least:

- Gate releases only after the formal profile is ready and the workload exits normally;
- one request increments `workload_runs_used` once; a failed attempt is also charged once and
  blocks further use of the same Session;
- Collection `actual_event_source`, `fallback_used`, and `fallback_reason` match the request;
- baseline and candidate have the same actual event source;
- correctness and Benchmark bind to their runs and the temporary container reports
  `cleanup_status = removed`;
- `partial`, unknown weight, resource lower bounds and forbidden conclusions remain visible;
- a built candidate that stops before comparison yields `not_evaluated`, not a fabricated
  Iteration.

If a historical symptom returns with matching packages and a new Session, preserve the Error ID,
request ID, Session/Build/Collection IDs and bounded journal, and treat it as a regression. Do not
retry repeatedly or modify sysctl, systemd capabilities, or Docker safety boundaries to prove it.
